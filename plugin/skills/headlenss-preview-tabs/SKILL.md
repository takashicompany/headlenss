# 成果物を headlenss の Web タブに出す

headlenss の Web UI (PC / スマホのブラウザ) でセッションのチャット画面を開くと、
画面のいちばん下に `チャット | <登録タブ…>` というタブ帯が出る。この登録タブに、
いま作っている HTML や dev server を並べられる。

```
  ← 戻る   mysession              ↻  ↗   [ tmux ][ chat ]
  ┌──────────────────────────────────────────────────────┐
  │                                                      │
  │   会話、または選んだタブの中身がここに出る            │
  │                                                      │
  ├──────────────────────────────────────────────────────┤
  │ [ チャット ][ レポート ][ 画面プレビュー ]            │  ← タブ帯
  └──────────────────────────────────────────────────────┘
```

タブ帯はチャット画面の中の切り替えで、ヘッダの `tmux | chat` とは別物。
登録が 1 件も無いセッションでは帯そのものが出ない (従来どおりのチャット画面)。

チャットで「できました」と言ってからユーザーがファイルを探しに行く必要がなくなるのが目的。
**成果物を作ったら、このタブに出すところまでが仕事。**

このスキルは環境非依存。ホスト名・ポート・パスはすべて自分の環境の値に読み替える。
**推測しない** (手順 0 で実際の値を確定させる)。

## 絶対に守ること

`headlenss-dev-server` スキルと同じ制約がそのまま効く。

- **headlenss が使っているポートを奪わない** (既定 3000 / 443 / 80)。`lsof` や `ss` で
  見つけても **kill しない**。
- **プロセスを kill しない。** `kill` / `pkill` / `killall` / PID 指定のシグナルで
  他人のプロセスを止めない。`ps` や `ss` で得た**親 PID・祖先 PID は診断情報であって
  停止対象ではない**。とくに tmux サーバー・`headlenss.service`・
  `/usr/lib/systemd/systemd --user`・自分が起動していない共有サービスは対象外。
- **`tailscale serve reset` を使わない** (全ポートの設定が消える)。
- **他人の行を書き換えない。** `.headlenss-plugins.conf` は 1 セッション 1 ファイルだが、
  自分が足した行以外は触らない。

## 0. 環境を調べる

セッションの中 (= tmux の pane) で実行する。

```bash
# このセッションの名前 (Web UI の URL とタブ一覧 API に使う)
tmux display-message -p '#S'

# このセッションの作業フォルダ (宣言ファイルの置き場所)
pwd

# headlenss サーバが生きているか (200 以外なら止まっている)
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/api/health
```

以後、セッション名を `<session>`、作業フォルダを `<cwd>` と書く。
サーバのポートが 3000 でない環境では URL を読み替える。

## 1. 宣言ファイルの書式

置き場所は **セッションの作業フォルダの直下** の `.headlenss-plugins.conf`。
1 行 1 件で `名前 = 値`。`#` 以降と空行は無視される。

```
# 名前 = 値       名前がそのままタブの見出しになる (日本語・空白 OK)

レポート     = report/index.html            ← ファイル型 (作業フォルダからの相対パス)
画面プレビュー = http://<host>:<port>/ web   ← URL 型 (dev server / PWA)。ブラウザ用は web 必須
```

値の書き方で 2 つの型に分かれる。

| 型 | 書き方 | 何が起きるか | どこに出るか |
|---|---|---|---|
| **ファイル型** | `report/index.html` のような**相対パス** | headlenss サーバがそのファイルを配信し、iframe に出す | Web のタブのみ (常に) |
| **URL 型** | `http://…` / `https://…` の**完全な URL** | その URL をそのまま iframe に出す | 行末のトークンしだい。無指定は Web + グラス両方 (下記) |

ファイル型で**受け付けられない書き方** (書いても黙って無視される):

- 絶対パス (`/home/...`)、`~` 始まり
- `..` を含むパス (作業フォルダの外は出せない)
- `.` で始まるセグメント (`.env`、`.git/config` のような隠しファイル)
- `\` `:` `?` `#` を含むもの
- 末尾が `/` のフォルダ指定 (ファイルを 1 つ指す)

URL 型は**完全な形** (scheme + host + port) で書く。ポート番号だけを書いてホストを
補わせる形式は無い。

### 【必須】ブラウザ確認用の URL には行末に `web` を付ける

この宣言ファイルは **Web のタブ** とグラス (G2) の **プラグイン一覧** で共有されている。
**URL 型の既定は「両方に出る」。** つまり `web` を付け忘れると、ブラウザで見るためだけの
プレビューが**グラスのセッション一覧にも並んでしまう**。グラスは画面が狭く、掛けたまま
使うものなので、ブラウザ用の項目が混ざるのは邪魔になる。

**このスキルで宣言する URL 型には、必ず行末に `web` を付けること。**

```
ブラウザ用 = http://<host>:<port>/ web      ← 必ずこう書く (Web のタブだけ)
両方       = http://<host>:<port>/ web g2   ← グラスからも開きたい時だけ
グラス専用 = http://<host>:<port>/ g2       ← グラスの一覧だけ (Web のタブには出ない)
無指定     = http://<host>:<port>/          ← 既定 = 両方に出る (= 付け忘れの形)
```

- トークンは `web` と `g2` の 2 つだけ。大文字小文字は問わない。打ち間違い (`wev` 等) を
  書くと**その行ごと無視される** (サーバのログに `[g2-plugins]` の警告が出る)
- **ファイル型に書く必要はない。** ファイル型 (相対パス) は常に Web のタブ専用で、
  グラスには最初から出ない。書いた対象は警告付きで無視される (パスは壊れない)

**サーバは URL の中身から出す先を推測しない。** 「ブラウザ用か / グラス用か」を
サーバ側から見分ける手掛かり (シム注入の有無など) は実測で当てにならなかったので、
自動判定は入れていない。**書いた人が `web` / `g2` で決める。**

## 2. 静的な HTML を出す (ファイル型)

作業フォルダの中に HTML があるなら、宣言を 1 行足すだけで終わり。ビルドも配置も要らない。

```bash
# 例: report/index.html を「レポート」というタブ名で出す
printf 'レポート = report/index.html\n' >> .headlenss-plugins.conf
```

ファイルが既にあるなら、これで Web UI のタブ帯に出る。

- **CSS / JS / 画像は相対パスで書く。** 宣言した HTML と同じ作業フォルダ配下なら
  そのまま読める (宣言していないファイルでも、HTML から相対パスで参照すれば配信される)。
- 配信は常に no-store なので、**ファイルを直せば再読込 (↻) で即反映される。**
- iframe は sandbox で閉じ込められる (親ページの localStorage / DOM には触れない)。
  外部 CDN の読み込みや `fetch` は使えるが、**ページ内で `localStorage` や
  Service Worker を使うものはファイル型では動かない**。それらが要るなら手順 3 の
  URL 型にする。

## 3. dev server / PWA を出す (URL 型)

Service Worker、`localStorage`、getUserMedia などが要るもの、あるいは HMR で開発中の
アプリは dev server として立て、URL 型で宣言する。

1. **`headlenss-dev-server` スキルの手順に従う。** ポートを選び (headlenss の
   占有ポートを避ける)、`0.0.0.0` にバインドして起動する。secure context が要るなら
   `tailscale serve --https=<port>` で HTTPS 化する。
2. できた URL を宣言する。**行末の `web` を忘れない** (付けないとグラスの一覧にも出る)。

```bash
printf '画面プレビュー = https://<host>.<tailnet>.ts.net:<port>/ web\n' >> .headlenss-plugins.conf
```

URL 型は別 origin として通常の iframe に載るので、Service Worker も localStorage も
そのまま動く。PWA のインストール確認など iframe では見られないものは、タブの
**↗ (別タブで開く)** から開く。

> **注意 (mixed content)**: headlenss の Web UI を `https://` で開いていて、宣言した
> URL が `http://` だと、ブラウザがフレーム内表示を止める。その場合はタブに理由が
> 表示されるので、`tailscale serve --https=<port>` で HTTPS 化するか、↗ で別タブに開く。

グラスからも開きたい場合だけ `web g2` と書き、`headlenss-g2-plugin` スキルを見ること
(戻れるようにするシムの話がある)。

## 4. 出たことを確認する

**宣言を書いただけで「できた」と言わない。** API で実際に返っていることを確かめる。

```bash
curl -s "http://127.0.0.1:3000/api/sessions/$(tmux display-message -p '#S')/webtabs"
```

期待する出力 (`tabs` に宣言したものが並ぶ):

```json
{"tabs":[
  {"name":"レポート","kind":"file","url":"/preview/mysession/report/index.html?v=1735600000000"},
  {"name":"画面プレビュー","kind":"url","url":"https://example.ts.net:5173/"}
]}
```

ファイル型なら、配信されている中身も見る (HTML が返れば成功):

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  "http://127.0.0.1:3000/preview/$(tmux display-message -p '#S')/report/index.html"
```

URL 型を宣言したら、**グラスの一覧に漏れていないか**も見る (`web` の付け忘れ検出)。

```bash
curl -s http://127.0.0.1:3000/api/claude/sessions \
  | python3 -c "import json,sys; [print(s['tmuxSessionName'], s.get('g2Plugins')) for s in json.load(sys.stdin)['sessions'] if s.get('g2Plugins')]"
```

このセッションの名前が出てきたら `web` が付いていない。宣言を直す。

最後に、ユーザーには**セッションのチャット画面を開いて、下のタブ帯のタブ名を押せばよい**
ことだけ伝える (URL を書くなら headlenss の Web UI の `/sessions/<session>?mode=chat` )。

## つまずいた時

| 症状 | 原因と確認 |
|---|---|
| `tabs` が空 | 宣言ファイルの置き場所が違う。**tmux セッションの作業フォルダ直下**か確認する (`pwd` と `tmux display-message -p '#S'` を突き合わせる) |
| ファイル型の行だけ出ない | 書き方が受け付けられていない (手順 1 の禁止リスト)。または指したファイルが存在しない。`ls <相対パス>` で確認 |
| **URL 型の行だけ出ない** | 対象に `g2` だけを書いている (グラス専用)。Web にも出すなら `web g2` にする |
| **ブラウザ用のはずがグラスの一覧にも出る** | 行末の `web` を付け忘れている (無指定の既定は両方)。`web` を足す |
| 行が丸ごと無視される | サーバのログに `[g2-plugins]` の警告が行番号と理由付きで出る |
| タブは出るが真っ白 | ファイル型なら `curl` で配信を確認 (上記)。URL 型なら dev server が `0.0.0.0` で listen しているか (`ss -tlnp`) |
| タブは出るが「ページ内に表示できません」 | mixed content (https の画面に http:// の URL)。HTTPS 化するか ↗ で別タブに開く |
| 帯が出ない | 登録が 0 件。手順 4 の curl で `tabs` を確認する。また、帯が出るのは **chat 画面だけ** (tmux 画面には出ない) |
| 直したのに古いまま | ヘッダの ↻ を押す (一覧を取り直して iframe を載せ替える) |
| 404 が返る | パスが作業フォルダの外を指している / 隠しファイルを指している。作業フォルダの中に置き直す |

## 関連

- dev server の立て方 (ポートの選び方・HTTPS 化・後片付け) → `headlenss-dev-server`
- 同じ宣言ファイルからグラス (G2) にプラグインを出す → `headlenss-g2-plugin`
- 新しいセッションを作る → `headlenss-new-session`
