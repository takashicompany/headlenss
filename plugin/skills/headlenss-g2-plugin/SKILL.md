# 開発中の G2 プラグインを headlenss から開けるようにする

headlenss (app 2.5.0 以降) は、tmux セッションのフォルダに置かれた宣言ファイルを読み、
そのセッションの下に G2 プラグインをぶら下げて表示する。グラスの一覧からタップすると
WebView ごとそのプラグインへ遷移する。

```
  myproject [Claude]       さっきの続きだけど…
▶   └ MyPlugin                       ← ここでタップすると開く
```

QR の再スキャンなしに開発中プラグインを開けるのが目的。

**このスキルは環境非依存。** 例に出てくるホスト名・ポート・パスはすべて置き換える前提で
書いてある。まず「0. 環境を調べる」で自分の環境の値を確定させること。

## 絶対に守ること

1. **ポート番号から「自分のサーバ」と判断しない。** 中身を取得して自分のものか確かめる
   (手順 3)。複数プロジェクトが同じポートを直書きしている事故が実際に起きている
2. **他プラグインの環境を壊さない。** ポートが埋まっていたら**自分が別のポートへ移る**。
   相手の dev server を落とす・設定を書き換える・共有ファイルの他人の行をいじる、はしない
3. **自分のプラグインの画面が出るのを見るまで「できた」と言わない** (手順 4-(3))
4. **プロセスを kill しない。** 共有プロキシを `kill` / `pkill` / `killall` / PID 指定の
   シグナルで止めない。`ps` や `ss` で得た**親 PID・祖先 PID は診断情報であって停止対象では
   ない**。子プロセスを止めたいからといって、親や祖先を kill しない

   以下は**絶対に停止対象に含めない**:

   - `/usr/lib/systemd/systemd --user` (ユーザーマネージャ本体)
   - cgroup が `user@<uid>.service/init.scope` のプロセス
   - tmux サーバー
   - `headlenss.service`
   - **自分が起動していない共有サービス全般**

   正常手順 (後述の `systemctl --user restart`) が失敗したら、**代替の kill 手段を
   発明せず、作業を止めてユーザーに確認する。**

   実際に起きた事故: 「設定を変えたらプロキシを再起動する」という手順に従い、稼働中
   プロキシの PID を `ps` の祖先チェーンで遡って node → sh → npm → systemd --user と
   まとめて kill した。末端が PID 1133 = systemd ユーザーマネージャ本体だったため、
   **ユーザーセッション全体 (headlenss、tmux 全 27 セッション) が落ちた。**

## 0. 環境を調べる (最初に必ずやる)

以下を確定させてから先へ進む。**推測しない。**

### headlenss サーバのアドレス

グラス側アプリの設定に入っている URL。サーバ側からは systemd / プロセスで確認できる。

```
systemctl --user status headlenss 2>/dev/null | head -3   # 常駐しているか
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/api/health
```

外から見えるアドレスは公開方法による。tailscale なら:

```
tailscale serve status
tailscale status --json | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['Self']['DNSName'].rstrip('.'), d['Self']['TailscaleIPs'][0])"
```

### リポジトリの場所

```
# headlenss (サーバ + G2 アプリ)
#   git@github.com:takashicompany/headlenss.git
# Plugin Loader (シム注入プロキシ。戻る動作に使う)
#   git@github.com:takashicompany-org/plugin-loader.git
```

置き場所は環境ごとに違う。以後 `<HEADLENSS>` `<LOADER>` と書く。

## 1. 導入 (未セットアップの環境で 1 回だけ)

### headlenss サーバ

```
git clone git@github.com:takashicompany/headlenss.git <HEADLENSS>
cd <HEADLENSS>/server && npm install
cp .env.example .env        # 必要なら編集
npm start                   # 常駐させるなら systemd user service にする
```

セッション検出のため **tmux が必要**。エージェントは tmux セッション内で起動する。

### グラス側アプリ

Even Hub のストア (Beta 配信) から入れるか、`<HEADLENSS>/even` で `npm run pack` して
生成される `.ehpk` を Even アプリに読み込ませる。**app 2.5.0 以降が必要**
(それ以前にこの機能は無い)。

初回起動時に、上で調べた headlenss サーバの URL を設定する。

### Plugin Loader のプロキシ (戻る動作を使う場合のみ)

```
git clone git@github.com:takashicompany-org/plugin-loader.git <LOADER>
cd <LOADER> && npm run install:all
```

対象を `<LOADER>/proxy/targets.json` に書く。目安のポート規約は
**プロキシ = ターゲット + 1000** だが、**空いている場合のみ**。

```json
[
  { "name": "myplugin", "target": "http://127.0.0.1:5173", "port": 6173 },
  { "name": "otherplugin", "target": "http://127.0.0.1:5190", "port": 6190 }
]
```

**追記のルール — 既存の行には触らない。**

このファイルは複数プラグインで共有される。他プラグインの行を書き換える・消す・
ポートを流用することは**しない**。相手が壊れる。

```
# 1. 既存の登録を確認する (自分の name / port が既に無いか、使いたい port が空いているか)
cat <LOADER>/proxy/targets.json

# 2. 自分の行だけを追記する。port が埋まっていたら自分が別のポートへずれる
```

`name` も重複させない。どのエントリが誰のものか分からなくなる。

プロキシは systemd ユーザーサービス `even-loader-proxy.service` として常駐させる運用。

```
systemctl --user status even-loader-proxy     # 動いているか
```

unit が無い環境では手動でも起動できる。

```
npm --prefix <LOADER> run proxy
```

ターゲットが未起動でもプロキシは落ちない (502 を返す)。常駐させてよい。

### 設定変更の反映 — 再起動しない

`targets.json` は**ホットリロードで自動的に反映される。再起動は要らない。**
書いたら数秒待ち、反映を確認する。

```
# unit 運用時: リロードのログが出る
journalctl --user -u even-loader-proxy -n 20

# 自分のエントリのポートが応答するか
curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 http://127.0.0.1:<プロキシポート>/
```

**壊れた JSON を書くと旧設定のまま動き続ける。**この場合もプロキシは落ちないので、
「応答があるから反映された」と判断しない。ログに理由が出ているので直す。

万一再起動が必要な場合 (ホットリロード未対応の古い構成等) は

```
systemctl --user restart even-loader-proxy
```

**これだけを使う。** unit が無い環境で手動起動 (`npm --prefix <LOADER> run proxy`) するのは
よいが、**既存プロセスの停止は自分でやらず、ユーザーに依頼する** (「絶対に守ること」4)。

## 2. 宣言ファイルを置く

tmux セッションの作業フォルダ**直下**に `.headlenss-plugins.conf` を作る。

```
# 形式: 名前 = URL [対象]
# '#' 以降と空行は無視される
MyPlugin = http://<自分のホスト>:6173
```

- **名前** はレンズの一覧にそのまま出る。短くする (幅が狭い)
- **URL は完全な形で書く**。scheme + ホスト + ポート。省略や推測はしない
- 1 行に 1 件。同じ名前が複数あれば先に書いた方が勝つ
- URL に `=` が含まれても壊れない (最初の `=` だけが区切り)

### 出す先を指定する (グラス / ブラウザ)

この宣言ファイルは **グラス (G2) の一覧** と **Web UI のプレビュータブ** で共有される。
どちらに出すかは、URL の後ろに空白区切りのトークンで書ける。

```
# 名前 = URL [web] [g2]
グラス専用 = http://<host>:6173 g2       ← グラスの一覧だけに出る
両方       = http://<host>:6173 web g2   ← グラスにも Web のタブにも出る
ブラウザ用 = http://<host>:4174 web      ← Web のタブだけ (グラスには出ない)
自動       = http://<host>:6173          ← 無指定。下の自動判定に任せる
```

- トークンは `web` と `g2` の 2 つだけ。大文字小文字は問わない
- URL に空白は書けないので、**トークンを足す前に書いた宣言はそのまま無指定として読まれる**
- 知らないトークン (`wev` のような打ち間違い) を書くと、**その行ごと無視される**
  (サーバのログに `[g2-plugins]` の警告が出る)

### 無指定のときの自動判定 — シムが入っていればグラスに出る

対象を書かなかった URL 型は、headlenss が疎通確認のときに **`?even_loader=1` を付けて
GET し、返ってきた HTML にシム注入のマーカーがあるか**を見る。

| 応答 | 判定 |
|---|---|
| シム注入あり (`__EVEN_LOADER_FROM_PROXY=1` / `/__even-loader/shim.js`) | **グラス + Web** |
| シム注入なし (普通の HTML) | **Web のタブだけ** |
| 応答なし | どちらにも出ない (従来どおり) |

理由: シムが入っているページは「グラスから開いて戻れるように用意されたもの」なので、
グラス向けだと判断できる。逆に素の HTML はブラウザで見るためのプレビューであることが多く、
グラスの一覧に混ぜたくない。

**注意 — プロキシも Vite プラグインも使っていない場合。** 素の dev server の URL を
直接書いていると、シムが無いので自動判定では**グラスに出なくなる**。その場合は
`g2` を明示的に書く (明示指定は自動判定より常に優先される)。

```
MyPlugin = http://<自分のホスト>:5173 g2
```

判定は 5 秒キャッシュされるので、conf を直したら数秒待ってから確かめる。

### URL の決め方

**グラス (スマホ) から届くアドレスを書く。** headlenss サーバのアドレスとは別物になる
ことが多い。

| 状況 | 書く URL |
|---|---|
| tailnet 経由 | `http://<tailnet のホスト名>:<ポート>` |
| 同一 LAN | `http://<PC の LAN IP>:<ポート>` |

**dev server は生の http。** headlenss サーバが `https://` で見えていても、それは手前の
リバースプロキシ (tailscale serve 等) が TLS 終端しているだけ。dev server のポートに
`https://` で繋ぐと応答が返らず固まる。**`http://` を書く。**

書いた URL が本当に届くかを、その場で確かめる。

```
curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 http://<ホスト>:<ポート>/
```

### git に含めるか

どちらでもよい。含めればチームや別マシンでも同じ設定が効くが、URL が環境依存なので
`.gitignore` する運用でも構わない。

## 3. dev server を起動し、**自分のものであることを確かめる**

ループバックだけに bind した dev server はスマホから届かない。

```
npm run dev -- --host 0.0.0.0
```

### 「そのポートが自分のサーバか」を必ず確認する

**ポート番号は当てにしてはいけない。** 複数のプロジェクトが同じポート (Vite なら 5173)
を直書きしていることは珍しくない。先に起動した別プロジェクトがそのポートを握っていると、
**他人のプラグインを自分のものと誤認する。**

実際に起きた事故: あるプロジェクトの `package.json` が `--port 5173` を指定していたが、
その時 5173 を握っていたのは別プロジェクトだった。ポートが LISTEN していることだけを見て
「自分の dev server が動いている」と判断し、宣言ファイルに書いてしまった。結果、グラスで
タップすると**まったく別のプラグインが開いた**。

確認は 2 通り。**両方通ること。**

**(a) 返ってきた中身が自分のものか**

```
# 自分のプロジェクトの index.html の title
grep -o '<title>[^<]*</title>' index.html

# その URL が実際に返す title
curl -s --max-time 5 http://127.0.0.1:<ポート>/ | grep -o '<title>[^<]*</title>'
```

**一致しなければ他人のサーバ。** title が無い/同一で判別できない場合は、自分だけが持つ
文字列 (アプリ名、固有の DOM id 等) で照合する。

**(b) そのポートの持ち主が自分のフォルダか** (Linux)

```
ss -ltnp | grep ':<ポート>'                  # pid= を読む
readlink /proc/<pid>/cwd                     # 自分のプロジェクトのパスか
```

macOS なら `lsof -nP -iTCP:<ポート> -sTCP:LISTEN`。

### ポートが他プロジェクトに使われていた場合

**必ず自分が動く。** 相手の dev server を落とす・設定を書き換える・ポートを奪うことは
しない。相手のプラグインが壊れる。

```
npm run dev -- --host 0.0.0.0 --port <空いているポート> --strictPort
```

- `--strictPort` を付ける。**付けないと Vite は黙って別のポートへずれる**ので、
  「意図したポートで動いている」保証が無くなる
- 恒久的に直すなら自分の `package.json` / `vite.config.ts` 側のポートを変える
- 空きの探し方: `ss -ltn | grep -c ':<候補> '` が 0 なら空き

変更後、**もう一度 (a)(b) を通してから**次へ進む。

## 4. 確認する

### (1) 宣言した URL が「自分のプラグイン」を返すか

headlenss が確かめるのは**応答があるかどうかだけ**で、中身が誰のものかは見ていない。
**ここは人 (またはエージェント) が確かめる。**

```
curl -s --max-time 5 <宣言したURL> | grep -o '<title>[^<]*</title>'
```

自分のプラグインの title と一致すること。**別名が返ったら、その URL は他人のもの。**
プロキシ経由なら、プロキシのターゲット設定が自分を指しているか `targets.json` を見直す。

シム注入も見ておく (方法 A を使う場合)。

```
curl -s --max-time 5 '<宣言したURL>?even_loader=1' | grep -c 'even-loader/shim.js'   # 1 以上なら注入済み
```

**この結果はそのまま「グラスに出るか」の自動判定と同じ。** 0 なのにグラスへ出したい場合は、
宣言に `g2` を足す (手順 2 の「出す先を指定する」)。

### (2) headlenss の一覧に出るか

headlenss サーバは**一覧に出す前に実際に接続して応答を確かめる**ので、出てくれば必ず
開ける。出てこない場合は届いていない。

```
curl -s http://<headlenssサーバ>/api/claude/sessions \
  | python3 -c "import json,sys; [print(s['tmuxSessionName'], s.get('g2Plugins')) for s in json.load(sys.stdin)['sessions'] if s.get('g2Plugins')]"
```

反映まで最大 5 秒かかる (確認結果をキャッシュしているため)。

### (3) 実際に開いて目で見る

**(1)(2) が通っても「自分のプラグインが開いた」ことの証明にはならない。**
グラス (または公式シミュレータ) でタップし、**自分のプラグインの画面が出ることを見る**まで
完了と報告しない。

過去に、他人のプラグインが開いていたのに「ゲームが開けます」と報告した事故がある。

## ダブルタップで headlenss に戻れるようにする

**開くだけなら何もいらない。** 戻る動作にはプラグイン側にシムが必要になる。

Even Hub の決まりで、プラグインはダブルタップで終了ダイアログを出す。headlenss 側から
この挙動は変えられない (イベントを受け取るのは遷移先だから)。そこで遷移先に小さな
スクリプト (シム) を入れ、終了処理を「前のページに戻る」にすり替える。

headlenss は遷移時に `?even_loader=1` を付けるので、**シムが入っていれば自動的に戻る**。
仕組みは Plugin Loader と共通で、headlenss 専用の対応は要らない。

### 方法 A: プロキシ経由 (プラグイン無改変)

手順 1 で立てたプロキシを使う。**プラグインのリポジトリには一切触らない。**
Vite 以外の dev server でも効く。

宣言ファイルには**プロキシ側のポート**を書く (例 6173)。ターゲット側 (5173) を書くと
シムが入らないので戻れない。

### 方法 B: Vite プラグイン (1 行追加)

自分のプラグインなら、こちらが手軽。

```ts
// vite.config.ts
import { evenLoaderInject } from '<LOADER>/tools/even-loader-inject'

export default defineConfig({
  plugins: [evenLoaderInject()],
})
```

`apply: 'serve'` なのでビルド成果物には入らない。この場合は生のポート (5173) を宣言
ファイルに書けばよい。

### どちらを選ぶか

| | 方法 A (プロキシ) | 方法 B (Vite) |
|---|---|---|
| 他人 / 無改変のプラグイン | **使える** | 使えない |
| Vite を使っていない | **使える** | 使えない |
| 準備 | プロキシを常駐させる | 1 行足すだけ |
| リポジトリ間の参照 | 不要 | `<LOADER>` へのパスが要る |

迷ったら A。プラグインに触らずに済み、リポジトリ間の依存も作らない。

## 挙動の仕様

- **一覧に出る = 必ず開ける。** サーバが接続確認を通したものだけが出る。dev server を
  落とせば 5 秒ほどで一覧から消える
- **カーソル**: セッション行とプラグイン行の両方に止まる。上下で移動、タップで実行
- **Connecting で固まった場合**: ダブルタップで中止して一覧に戻る
- **戻ってきた後**: headlenss はレンズを描き直す (画面生成 API はセッションにつき 1 回
  きりなので、復帰時は再構築 API に切り替わる)

## つまずいた時

| 症状 | 原因 |
|---|---|
| **別のプラグインが開く** | ポートを他プロジェクトに取られている。手順 3 の (a)(b) で持ち主を確認し、自分が別ポートへ移る |
| 一覧に出ない | URL に届いていない。手順 2 の curl で確認する |
| **一覧に出ない (curl も届く)** | シムが入っていないので Web のタブ専用と判定された。`curl -s '<URL>?even_loader=1' \| grep -c even-loader/shim.js` が 0 なら、宣言に `g2` を足す |
| **Web のタブに出したくないのに出る** | 宣言に `g2` だけを書く (無指定と `web g2` は Web にも出る) |
| 一覧に出ない (curl は通る) | 宣言ファイルの置き場所が違う。tmux セッションの**作業フォルダ直下**か確認 |
| Connecting で止まる | URL は書けているが実際には届いていない。`https://` を書いていないか確認 |
| 開けるが戻れない | シムが入っていない。方法 A か B を入れる |
| **targets.json を書いたのに反映されない** | ホットリロードのログを確認 (`journalctl --user -u even-loader-proxy -n 20`)。壊れた JSON を書くと旧設定のまま動き続ける (エラーログに理由が出る)。プロキシを kill しない |
| 書式が効かない | サーバのログに `[g2-plugins]` の警告が出る。行番号と理由が書かれている |
| そもそも機能が無い | グラス側アプリが 2.5.0 未満。更新する |

## 関連

- 同じ宣言ファイル (`.headlenss-plugins.conf`) は headlenss の Web UI (PC / スマホ) の
  プレビュータブにも使われる。出す先はトークン (`web` / `g2`) と自動判定で決まる。
  作った HTML を相対パスで宣言して Web だけに出す方法は `headlenss-preview-tabs` スキルへ。
- dev server の立て方 (ポートの選び方・HTTPS 化) は `headlenss-dev-server` スキルへ。
